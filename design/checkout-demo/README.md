# Локальный сценарий заказа с оплатой картой

Запуск после сборки сайта: `node design/checkout-demo/build.mjs`.
Создаёт семь связанных фреймов в `dist/__preview/checkout-demo/` и
синтетические записи в отдельной схеме локального PostgreSQL `checkout_demo`.
Не изменяет `public.shop_orders`, аккаунты, корзину или права пользователей.
Повторный запуск обновляет те же демонстрационные записи без создания дублей.

Фреймы — макеты состояний, не подключённый checkout. Кнопки переходят между
страницами; они не вызывают API ЮKassa и не изменяют базу. В базе заранее
записан успешный итог и последовательность состояний. Экран отмены — отдельная
альтернативная ветка, не состояние того же успешного платежа.

Пример: розничная цена одного товара из текущего каталога, без дисконтной карты,
самовывоз бесплатно. Все контакты вымышленные. Полный номер карты, CVV и
банковские коды не запрашиваются и не сохраняются.

Схема `checkout_demo`:
- `shop_orders`: пример заказа, контактов и состава товаров;
- `payments`: отдельная запись платежа, связанная с заказом;
- `payment_history`: демонстрационная последовательность состояний.
Это предложенная модель платежей, не внедрённая миграция рабочего API.

Сценарий картой: pending → waiting_for_capture → succeeded.
Резервирование не называем полученной оплатой. Переход по return_url сам по
себе не подтверждает оплату: рабочий бэкенд должен проверить статус платежа,
сумму, валюту и связь с заказом; обрабатывать повторные уведомления идемпотентно.
Срок удержания берётся из expires_at. Подтверждение банка может не потребоваться.
Методы без двухстадийной оплаты требуют отдельного сценария.
Условия чеков и маркировки необходимо подтвердить для конкретного магазина;
данный макет не формирует чеки и не имитирует их доставку.

Источники:
- https://yookassa.ru/developers/payment-acceptance/getting-started/payment-process
- https://yookassa.ru/developers/using-api/webhooks


Первый шаг использует существующую страницу сайта
`/checkout/?buy=alfalfa&qty=1` с согласованной 17 ноября формой: генератор
перенаправляет на неё, не создавая альтернативную разметку оформления.
Корзина владельца при этом не меняется. Кнопка оплаты этой страницы сохраняет
текущее поведение-заглушку; этапы ЮKassa показаны в соседних фреймах отдельно.
