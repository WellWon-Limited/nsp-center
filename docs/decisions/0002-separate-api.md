# Отдельный бэкенд при сохранении сайта и локальной базы

Дата: 17 ноября 2026. Область: локальная ветка `refactor/separate-apps-local`.

Когда сотрудник сохраняет товар или покупатель входит в кабинет, запрос теперь
обрабатывает самостоятельный процесс `apps/api/server.mjs`. Сервер страниц
`scripts/serve.mjs` проксирует `/api/`, не читает секретный `.env` и не подключается
к PostgreSQL. Сайт и интерфейс админки пока остаются одним React-приложением.

## Границы

- `apps/api/`: аккаунты, служебные права, товары, цены, заказы, заявки на карты,
  файлы, материалы консультанта, СДЭК. Инициализация схемы и работа с пулом
  PostgreSQL принадлежат только API.
- `packages/domain/`: общие проверки и преобразования без React и базы.
  Совместимые точки импорта в прежних каталогах не содержат копий реализации.
- `packages/catalog/generated/content.json`: полный подготовленный каталог для API.
  `public.json`: публичная версия для сервера страниц. Браузерный summary
  по-прежнему собирается отдельно. Партнёрские цены из публичных товаров исключены.
- `scripts/catalog-pages.mjs`: формирование HTML по данным
  `GET /api/storefront/page?path=…`. Этот маршрут также даёт новые товары,
  статьи и дополнительные адреса sitemap. Доступ к БД из рендера удалён.
- PostgreSQL остаётся существующим отдельным процессом с прежними данными.

Перенос всех исходных товаров в БД не требуется для этого этапа. Смена React/Vite,
полноценное отделение админки, внедрение оплаты и переработка миграций сюда не входят.

## Запуск и размещение

Команды и переменные описаны в [DEVELOPMENT.md](../DEVELOPMENT.md).
API работает без `src/`, `dist/`, HTML-шаблонов и сборки Vite. Для локального
компьютера проверена связь через Unix-сокет `/tmp/nsp-center-api.sock`; для
раздельных контейнеров — HTTP. Сокет доступен только владельцу. API и web
запущены отдельными службами Factory; прежний монолитный процесс на 5217 остановлен.
PostgreSQL не перезапускалась. Основная ветка и удалённый стенд не менялись.

Dockerfile имеет независимые цели `api` и `web`; compose не создаёт новую БД.
Для будущей публикации нужно обновить конфигурацию размещения с одного сервиса
на два. Локально Docker отсутствует, поэтому образы не были собраны; соответствующие
сборки и HTTP-проверки добавлены в CI.

## Доказательства

- `tests/separate-api.test.mjs`: API запускается из временного каталога без
  исходников фронтенда; web работает отдельным процессом. Временная PostgreSQL
  проверяет вход, cookie, CSRF, разграничение прав, корзину, загрузку файла,
  создание товара и категории, публичные цены и восстановление после перезапуска API.
- Внутри интеграционного теста выполняются проверки всех 227 адресов снимка,
  индексирования, актуального служебного входа и прототипа — без пропусков.
- `tests/docker-runtime.test.mjs`: проверяются границы импортов и состав образов.
- Проверены 200 для главной, каталога, `/api/site`, `/api/health`, sitemap и
  401 для входа в покупательскую/служебную сессию без cookie на текущем локальном стенде.
- Главная открыта в холсте Factory в телефонном фрейме, HTTP 200. Диагностика
  фиксирует сообщения ResizeObserver и предупреждения предзагрузки изображений;
  чистая консоль и полная визуальная регрессия этим этапом не подтверждены.
- Последний `npm run check`: сборка успешна; 245 тестов прошли, один упал,
  четыре внешних HTTP-теста пропущены (они отдельно выполнены внутри интеграционного).
  Сверка контента отдельно: 9 проверок, 0 проблем.

## Известный независимый сбой общего gate

В коммите-точке возврата `1a885aa` сохранены дизайн-черновики из `public/images/`.
Тест использования изображений проверяет только отслеживаемые Git файлы, поэтому
после этого коммита он обнаруживает неиспользуемые рабочим сайтом изображения.
Исходный тест из `1a885aa` воспроизводит тот же сбой. Сам тест не ослаблялся,
материалы не удалялись. Общий gate нельзя считать зелёным до отдельного решения
о размещении этих черновиков.
