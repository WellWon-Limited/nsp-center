# Сотрудник — отдельный аккаунт с отдельным входом

Раньше «Управление сайтом» было частью личного кабинета покупателя с ролью `admin`. По исследованию (Shopify,
WooCommerce, InSales, Tilda, 1С-Битрикс, кабинеты Ozon и Wildberries; OWASP) сотрудник — отдельный аккаунт:

- вход только на `/admin/` (`/api/admin/login`), своя cookie `nsp_staff` (SameSite=Strict), сессия 12 часов;
- обычный вход покупателя служебный аккаунт не пускает, а покупатель не входит в управление;
- регистрация никогда не даёт прав сотрудника; `ADMIN_EMAILS` больше не читается;
- первого сотрудника создаёт `npm run admin:create`, остальных — раздел «Сотрудники» (одноразовый пароль,
  почту покупателя дать нельзя, удалённый сотрудник не входит);
- `/admin/` закрыт от поиска (`noindex`, нет в карте сайта) и не хранится офлайн.

Отложено: роли «Владелец / Менеджер / Контент», второй шаг входа (код из приложения), выход после простоя,
журнал действий на экране. Решение владельца 2026-11-10.

Код: `scripts/accounts.mjs` (`staffAuth`, `staffUser`), `scripts/site-admin.mjs`, `src/admin.tsx`.
Проверка: `tests/accounts.test.mjs`.
