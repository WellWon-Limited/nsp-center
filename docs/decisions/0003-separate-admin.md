# Отдельная админка со встроенным предпросмотром

Дата: 17 ноября 2026. Ветка: `refactor/separate-apps-local`.

## Пользовательский результат

Сотрудник открывает отдельную админку, меняет товар или статью и видит черновик
до сохранения. Предпросмотр не загружает страницы покупательского сайта и
работает при остановленном сервере сайта. Данные и загруженные файлы по-прежнему
требуют доступного API и PostgreSQL. Просмотр не публикует изменения.

## Границы

- `apps/admin/`: редакторы, собственное состояние сотрудников, точка входа,
  Vite-конфигурация и сервер. Результат сборки — `dist-admin/`.
- `src/App.tsx`: покупательские маршруты; редакторы больше не импортируются.
- `packages/presentation/`: общий вход в компоненты оформления и стили.
  Реализации пока остаются в общем `src/`; их код включается в обе сборки.
  Это общая зависимость исходников, а не обращение к работающему сайту.
- `apps/api/`: единый API для обоих клиентов. Только он читает секреты и БД.
- PostgreSQL: прежний локальный процесс и прежние постоянные данные.

Админка не запускает покупательский StoreProvider, не восстанавливает его
localStorage и не синхронизирует аккаунт, корзину или план. Общий React-контекст
получает собственное состояние сотрудников; предпросмотр получает состояние
анонимного покупателя с отключёнными изменяющими действиями.

Полная карточка товара и тексты исходных FAQ/видео получаются через
`GET /api/admin/preview-data?product=…` или `?page=…`. Доступ проверяется
серверной сессией сотрудника; покупатель и анонимный запрос получают 401.
Шапка отрисовывается тем же React-компонентом, что и на сайте, без fetch HTML.
Сохранённые данные и несохранённая форма объединяются прежним механизмом
`previewProduct`; тесты сохраняют проверку частичных изменений и медиа.

Диалог вынесен порталом в body: масштаб административного редактора больше
не увеличивает диалог за пределы экрана. Внутренний iframe создаётся через
srcDoc и заполняется локальными компонентами; это не iframe с URL сайта.

`/office-k7m4q9/` на сайте перенаправляет в `ADMIN_ORIGIN`, сохраняя query.
`/admin/` остаётся 404. На отдельном сервере админки доступны `/` и служебный
путь, все ответы закрыты от индексации. «Открыть сайт/товар/статью» использует
`SITE_ORIGIN`; для работы предпросмотра этот адрес не используется.

Docker/compose имеют отдельные api/admin/web цели и процессы. CI проверяет
образы, в том числе доступность админки после остановки web. Локально Docker
отсутствует: эти команды здесь не выполнялись.

В консоли браузера остаются предупреждения `ResizeObserver loop completed with
undelivered notifications`; подобные сообщения наблюдались и до разделения.
Проверенные сценарии работают, но чистая консоль не заявляется.

Не заявляется полный ручной проход каждой формы и каждого товара. Изменения
общего оформления надо выпускать в обе сборки, иначе версии могут различаться.
Встроенный просмотр не проверяет оформление заказа и другие действия покупателя.

## Локальный запуск

Сайт: http://127.0.0.1:5217/. Админка: http://127.0.0.1:5218/.
API использует `/tmp/nsp-center-api-v2.sock`; эти три процесса запущены через
Factory напрямую командой node, чтобы остановка доходила до обработчика сигнала.
Старый сокет после остановки через npm остался без слушателя; он не удалялся.
База на 8700 не перезапускалась. Реестр Factory умеет закреплять один web-порт
на проект и возвращает существующий 5217; дополнительный процесс админки на
5218 виден в списке управляемых серверов, но не закреплён отдельной строкой.
Реестр вручную не изменялся.

Команды сборки и запуска — [DEVELOPMENT.md](../DEVELOPMENT.md).

## Уточнение причины ResizeObserver, 17 ноября

Наблюдатели шапок и масштаба предпросмотра теперь ставят измерение в следующий
кадр через общий `observeLayout`; запись высоты шапки выполняется только при
изменении значения. Отложенная работа отменяется при закрытии компонента.
Карточка в iframe использует ResizeObserver и requestAnimationFrame своего
документа. Прямой пересчёт блока личного плана также вынесен из callback.
Два теста проверяют объединение уведомлений, отсутствие синхронной записи,
отмену после закрытия и отсутствие повторной записи неизменившейся высоты.

Однако все предупреждения холста этим не устранены. Контрольная HTML-страница
без приложения и без единого ResizeObserver тоже получила три таких события
(примерно через 40, 1227 и 8420 мс). Её единственный script лишь регистрировал
window.error. Это воспроизводит проблему в среде Factory вне кода проекта;
конкретный внутренний модуль Factory не установлен. Создан локальный отчёт
«ResizeObserver на пустой странице» командой cv bugreport; он не отправлялся.

Временные диагностические скрипты убраны. `npm run check`: 255 тестов,
250 успешных, 4 условно пропущенных, прежняя ошибка неиспользуемых изображений.
Предупреждения о preload изображений на главной — другая проблема и не исправлялись.
