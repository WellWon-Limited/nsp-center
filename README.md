# NSP Center

Адаптивный сайт на основе `assets/NSP App Prototype.html` и локального снимка
`references/nsp-center.ru/`. Дизайн прототипа перенесён в общую систему:
Manrope, мятные/голубые/песочные акценты, полупрозрачные панели и мобильная
навигация. Большой экран использует те же компоненты.

## Запуск

Нужны Node.js 22.12+ и npm. Проверено на Node 25.2.0 / npm 11.6.2.

```sh
npm ci
npm run build
npm run preview
```

Сайт: http://127.0.0.1:5217/ · [Дизайн-система](http://127.0.0.1:5217/design-system/) ·
[Прототип приложения](http://127.0.0.1:5217/app-prototype/).
Тестовый сервер: https://nsp-center.dev.codimax.ru. Что где лежит — [карта проекта](docs/MAP.md).
Для разработки после `npm run content`: `npm run dev` (тот же порт 5217; одновременно с preview не запускается).

## Что работает

- Все 227 адресов снимка: 166 товаров, 17 разделов каталога с пагинацией,
  8 статей, список блога, главная и 16 информационных страниц.
- Поиск по названию/артикулу/назначению, сортировка, наличие, избранное.
- Галереи товаров, полные составы и характеристики, описания, 254 ссылки на
  документы. Все вкладки содержатся в HTML ещё до запуска JavaScript.
- Корзина и локальные черновики заказов, профиль, план приёма, марафон привычек,
  анкета из пяти вопросов. Состояние сохраняется в браузере.
- Контактная форма готовит письмо для почтового приложения. Отправки на сервер нет.
- 238 отдельных HTML-документов, 13 перенаправлений старых адресов товаров,
  sitemap, canonical, уникальные заголовки статей, Product/Offer JSON-LD.

Оплата, серверный аккаунт, отправка заказов и живой консультант не подключены.
Цены и наличие относятся к сохранённому снимку. Product reviews отсутствуют в
снимке; оценки сохранены, тексты отзывов не выдумываются. `/photo/`, `/shares/`
и исходный `/health-marafon/` не содержали материала; это отмечено в аудите.
Видео открываются по сохранённым внешним ссылкам YouTube.

## Репозиторий и доступ

- **Код:** https://github.com/WellWon-Limited/nsp-center — закрытый
  репозиторий в организации WellWon-Limited. Посторонние его не видят, у
  участника организации доступ только к тем репозиториям, которые ему открыли.
- **Dev-сайт:** https://nsp-center.dev.codimax.ru. Любое изменение, принятое в
  главную ветку (`main`), само выкладывается сюда примерно за 5–10 минут.
- **Как вносят правки:** участник не может менять главную ветку напрямую. Он
  делает отдельную ветку и запрос на слияние (pull request). GitHub сам
  проверяет запрос: собирается ли сайт, проходят ли тесты и запускается ли
  сервер dev-сайта. Когда обе проверки зелёные, участник сам вливает запрос,
  одобрение владельца не нужно, и через 5–10 минут правка на dev-сайте. С
  красной проверкой GitHub влить запрос не даст.
- **Владелец** может отправлять изменения в главную ветку напрямую, правила
  защиты на него не действуют.
- **Участники** работают под общим аккаунтом `wellwon-team` (запись только в
  этот репозиторий, вход с подтверждением 2FA). Логин и пароль передаются
  отдельно, не в git и не агенту. Чтобы было видно, кто что сделал, каждый
  указывает в своей копии своё имя и почту: они видны в коммитах, а автором
  запроса на слияние GitHub показывает `wellwon-team`.
- **Подключение нового участника:** владелец передаёт логин и пароль от
  `wellwon-team` и текст для агента из `CONTRIBUTING.md`, вписав почту
  участника. Агент участника сам настроит вход, скачает проект и прогонит
  проверки.

Что стоит помнить:

- Автоматическая проверка кода на GitHub запускается при каждой отправке.
  Репозиторий закрытый, поэтому каждая проверка тратит бесплатные минуты
  организации.
- Схема приложения открыта на dev-сайте по адресу
  https://nsp-center.dev.codimax.ru/app-prototype/ — её видит любой, кто знает
  адрес.

независимые проверки требуют его.
