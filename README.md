# NSP Center

Адаптивный сайт на основе `assets/NSP App Prototype.html` и локального снимка
`references/nsp-center.ru/`. Дизайн прототипа перенесён в общую систему:
Manrope, мятные/голубые/песочные акценты, полупрозрачные панели и мобильная
навигация. Большой экран использует те же компоненты.

## Запуск

Нужны Node.js 22.12+ и npm. Проверено на Node 26.13.0 / npm 11.20.0.

```sh
npm ci
npm run build
npm run api      # отдельный терминал: API, читает локальный .env
npm run preview  # отдельный терминал: сайт и админка
```

Сайт: http://127.0.0.1:5217/ · [Дизайн-система](http://127.0.0.1:5217/design-system/) ·
[Прототип приложения](http://127.0.0.1:5217/app-prototype/) ·
[Управление сайтом](http://127.0.0.1:5217/admin/) (вход для сотрудников).
Тестовый сервер: https://nsp-center.dev.codimax.ru. Что где лежит — [карта проекта](docs/MAP.md).
Для разработки при работающем `npm run api`, после `npm run content`: `npm run dev` (тот же порт 5217; одновременно с preview не запускается).

Аккаунты локально: `npm run db:local` (Postgres на этом компьютере), `npm run db:seed` (тестовые
аккаунты), `npm run admin:create -- <почта>` (первый сотрудник). Без базы (`DATABASE_URL` не задан)
сайт работает с пробным аккаунтом в браузере. Подробно — [разработка](docs/DEVELOPMENT.md).

## Что работает

- Все 227 адресов снимка и 4 новых товара: 170 товаров, 17 разделов каталога с
  пагинацией, 8 статей, список блога, главная и 16 информационных страниц; 90
  страниц-тем `/temy/…` («для чего нужен витамин D3») с товарами «с чем сочетают».
- Поиск по названию/артикулу/назначению, сортировка, наличие, избранное, лист ожидания.
- Галереи товаров, полные составы и характеристики, описания, 254 ссылки на
  документы, комментарии экспертов из лекций врачей. Все вкладки содержатся в
  HTML ещё до запуска JavaScript. Отзывы покупателей появляются после проверки
  сотрудником (нужен сервер аккаунтов).
- Аккаунты покупателей на Postgres: регистрация и вход только по российской почте,
  телефон необязателен (маска +7), выход с подтверждением; корзина, избранное, план
  приёма и черновики заказов хранятся в аккаунте и видны на любом устройстве.
- Корзина по логике маркетплейсов (галочки, доставка и скидка в итоге), черновики
  заказов, «Мои покупки», профиль, план приёма по датам, марафон привычек,
  тест-рекомендации из восьми вопросов, уведомления в колокольчике.
- Цены: розничная видна всем; цену по дисконтной карте видит только вошедший
  покупатель с номером карты в профиле.
- Чат `/consultation/`: бот-помощник по лекциям врачей и страницам магазина; связь
  с человеком — звонок или почта. Нейросеть подключается ключом, по умолчанию выключена.
- Управление сайтом `/admin/` — отдельный вход сотрудников; разделы «Сводка»,
  «Заказы», «Товары», «Курс у.е.», «Отзывы», «Чат-консультант», «Сотрудники».
- Приложение (PWA): сайт ставится на телефон, план и марафон работают без сети,
  напоминания о приёме.
- Контактная форма готовит письмо для почтового приложения. Отправки на сервер нет.
- 334 отдельных HTML-документа, 13 перенаправлений старых адресов товаров,
  sitemap, canonical, уникальные заголовки статей, Product/Offer JSON-LD.

Не сделано: оформление заказа и оплата на сайте, проверка номера дисконтной карты
по базе NSP, роли сотрудников и второй шаг входа в управление, проверка на настоящих
телефонах. На dev-стенде пока нет базы данных, поэтому аккаунты, цены по карте и управление
сайтом там не работают (действует только пробный аккаунт в браузере).
Цены — прайс NSP в у.е. × курс, который задаёт сотрудник. Отзывов покупателей в
снимке не было; оценки старого сайта не показываются, тексты отзывов не
выдумываются. `/photo/`, `/shares/` и исходный `/health-marafon/` не содержали
материала; это отмечено в аудите. Видео открываются по сохранённым внешним ссылкам YouTube.

## Репозиторий и доступ

- **Код:** https://github.com/WellWon-Limited/nsp-center — открытый
  репозиторий в организации WellWon-Limited. Читать и скачивать код может любой,
  вносить изменения — только участники, которым дали доступ.
- **Dev-сайт:** https://nsp-center.dev.codimax.ru. Любое изменение, принятое в
  главную ветку (`main`), само выкладывается сюда примерно за 5–10 минут.
- **Как вносят правки:** участник не может менять главную ветку напрямую. Он
  делает отдельную ветку и запрос на слияние (pull request). GitHub сам
  проверяет запрос: собирается ли сайт, проходят ли тесты и запускается ли
  сервер dev-сайта. Когда обе проверки зелёные, участник сам вливает запрос,
  одобрение владельца не нужно, и через 5–10 минут правка на dev-сайте. С
  красной проверкой GitHub влить запрос не даст.
- **Владелец** может отправлять изменения в главную ветку напрямую, правила
  защиты на него не действуют.
- **Участники** работают под общим аккаунтом `wellwon-team` (запись только в
  этот репозиторий, вход с подтверждением 2FA). Логин и пароль передаются
  отдельно, не в git и не агенту. Чтобы было видно, кто что сделал, каждый
  указывает в своей копии своё имя и почту: они видны в коммитах, а автором
  запроса на слияние GitHub показывает `wellwon-team`.
- **Подключение нового участника:** владелец передаёт логин и пароль от
  `wellwon-team` и текст для агента из `CONTRIBUTING.md`, вписав почту
  участника. Агент участника сам настроит вход, скачает проект и прогонит
  проверки.

Что стоит помнить:

- Автоматическая проверка кода на GitHub запускается при каждой отправке.
  Репозиторий открытый, поэтому проверки не тратят минуты организации.
- Схема приложения открыта на dev-сайте по адресу
  https://nsp-center.dev.codimax.ru/app-prototype/ — её видит любой, кто знает
  адрес.

## Проверки и исходники

```sh
npm run check
WW_TEST=1 WW_TEST_ID=nsp-acceptance npm run preview
# В другом терминале:
NSP_TEST_URL=http://127.0.0.1:5217 npm test
```

`npm run check` — сборка, TypeScript, 159 тестов (без `NSP_TEST_URL` 3 из них
пропускаются) и сверка со снимком (9 проверок).

[Разработка](docs/DEVELOPMENT.md) · [Дизайн-система](docs/DESIGN-SYSTEM.md) ·
[Прототип приложения](docs/PROTOTYPE.md) ·
[Аудит](docs/CONTENT-AUDIT.md) · [Приёмка через холст](docs/VERIFICATION.md).

Снимок является источником сборки: `raw/`, `data/` и `assets/` сохранены без
изменений. В git исключены только производные копии `public/media/`,
`public/prototype/`, `packages/catalog/generated/` и `dist/`, чтобы не хранить изображения
дважды. Архив источника намеренно оставлен доступным для git: чистая сборка и
независимые проверки требуют его.

Админка запускается отдельно: `npm run admin` (по умолчанию порт 5218).
Сайт — `npm run preview` (5217), API — `npm run api`, база — существующая локальная
PostgreSQL. `npm run build` собирает сайт и админку. Предпросмотр встроен в сборку
админки и работает без сервера сайта; для данных нужен API.
Команды и настройки: [разработка](docs/DEVELOPMENT.md).
